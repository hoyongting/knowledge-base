# GitHub 连接排障记：从 DNS 污染到握手成功

> 一次漫长的网络问题诊断实录。记录问题、定位思路与最终解法，供以后遇到类似问题时参考。

## 📌 问题现象

在配置 GitHub 连接器时，浏览器始终无法打开 GitHub：
- 初期：浏览器报"连接超时"
- 后期：出现"我不是机器人"验证页，但验证组件加载不出来
- 授权页的 Authorize 按钮始终是灰色，无法点击

## 🔍 诊断过程

### 第一层：DNS 污染
`nslookup github.com` 解析到 `20.247.166.64`（Azure 段），而 GitHub 官方 IP 应为 `140.82.x.x`。

**验证**：DoH 查询 `github.com` 同样返回污染 IP。

**解法**：在 `C:\Windows\System32\drivers\etc\hosts` 钉入官方 IP。

### 第二层：节点连通性差异
不同网络出口下，GitHub 各节点的连通性不同：

| 节点 | 广电热点 | 说明 |
|------|---------|------|
| 140.82.112.3 | ❌ 不通 | 曾被 hosts 钉死于此 |
| 140.82.113.3 | ✅ 通 | 最终采用 |
| 140.82.114.3 | ✅ 通 | |
| 140.82.121.3 | ✅ 通 | |

**教训**：`ping` 通不代表 `443` 端口通。要用 `Test-NetConnection -Port 443` 逐个测。

**解法**：换成能通的节点，flushdns 后 `Invoke-WebRequest https://github.com` 返回 HTTP 200。

### 第三层：静态资源域名
即使主站能开，页面样式仍是宋体、Authorize 按钮灰色——说明 CSS/JS 没加载。

**原因**：静态资源在 `github.githubassets.com`，未钉 hosts。

**解法**：加入 CDN 节点 `185.199.108-111.215`。

### 第四层：DoH 绕过 hosts
Firefox 默认开启加密 DNS（DoH），会**绕过 hosts 文件**自己查 DNS，导致前面的修改全部失效。

**验证**：DoH 查询 `github.com` 仍返回污染 IP `20.247.166.64`。

**解法**：在 Firefox 配置目录的 `user.js` 写入：
```js
user_pref("network.trr.mode", 5);  // 5 = 彻底关闭 DoH
user_pref("network.dns.disablePrefetch", true);
```
**注意**：必须完全退出 Firefox（进程清零）后重启才生效。

### 第五层：浏览器兼容性
IE 早已不被 GitHub 支持，JS 跑不动 → 按钮永远灰色。

**解法**：换用现代浏览器（Firefox / Edge / Chrome）。

## ✅ 最终方案清单

1. hosts 钉入 GitHub 官方 IP（选当前网络下 443 能通的节点）
2. hosts 钉入静态资源 CDN（`githubassets.com` 等）
3. 关闭 Firefox 的 DoH（user.js），重启浏览器
4. 使用现代浏览器完成授权

## 💡 经验总结

- **分层排查**：DNS → TCP 端口 → TLS → 静态资源 → 浏览器，逐层定位
- **ping 不等于可用**：一定要测目标端口
- **DoH 是 hosts 的天敌**：改了 hosts 不生效，先想到它
- **不同网络出口结果不同**：换网络后要重新测节点
